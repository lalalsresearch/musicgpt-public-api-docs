---
title: Complete Audio Upload
openapi: 'POST /v2/upload_audio/{upload_id}/complete'
---

**Complete Audio Upload** verifies an uploaded file and marks it ready for use.

This is step 2 of the upload flow. Call it after the S3 upload from [Create Audio Upload](/api-documentation/endpoint/upload-audio-create) succeeds. The API reads the object's metadata and confirms it matches the reservation: exact size, content type, checksum when one was declared, and a magic-byte probe proving the bytes really are audio. For an `application/zip` reservation, the probe instead confirms the object is a readable zip holding at least one audio file.

Only after this call does the `upload_id` become usable by `POST /MusicAI` or `POST /Remix` (v2).

<Info>
  This route verifies and nothing else. To have the file accelerated on a generation backend ahead of a remix — and to be told when that's finished — finish the upload with [Complete Preprocess Audio Upload](/api-documentation/endpoint/upload-audio-complete-preprocess) instead.
</Info>

<Note>
  Idempotent: repeating this call for an already-verified upload returns the same result rather than an error.
</Note>

---

## Endpoint

```http
POST /api/public/v2/upload_audio/{upload_id}/complete
```

---

## Try It Yourself

Use the [Upload Endpoint Explorer](/api-documentation/endpoint/upload-audio-complete) to verify an upload with your own `upload_id`.

---

## Path Parameters

| Parameter    | Type   | Required | Description                                    |
| ------------ | ------ | -------- | ----------------------------------------------- |
| `upload_id`  | String | Required | The identifier returned by `POST /upload_audio` |

---

## Returns

A `Complete_Audio_Upload_Response` object:

| Field                | Type    | Description                                                           |
| -------------------- | ------- | ----------------------------------------------------------------------- |
| `success`            | Boolean | Whether the upload passed verification                                 |
| `message`            | String  | A descriptive status message                                           |
| `upload_id`          | String  | The verified upload identifier. Pass this to `POST /MusicAI` or `POST /Remix` (v2). |
| `expires_in_seconds` | Integer | How long the upload stays referenceable                                |

---

## Sample Request (Python)

```python
import requests

upload_id = "upl_x7Kd2mQ..."
url = f"https://api.musicgpt.com/api/public/v2/upload_audio/{upload_id}/complete"

headers = {"Authorization": "<API_KEY>"}

response = requests.post(url, headers=headers)
print(response.json())
```

---

## Sample Response

```json
{
  "success": true,
  "message": "Upload ready",
  "upload_id": "upl_x7Kd2mQ...",
  "expires_in_seconds": 86400
}
```

---

## Errors

| Status | Code                   | Meaning                                                                  |
| ------ | ---------------------- | --------------------------------------------------------------------------- |
| 400    | `BAD_REQUEST`           | Malformed `upload_id` or no file uploaded yet                              |
| 404    | `RESOURCE_NOT_FOUND`    | Upload doesn't exist, has expired, or belongs to another customer          |
| 422    | `UNPROCESSABLE_CONTENT` | Stored object doesn't match size, type, or checksum, isn't audio, or is a zip with no audio files |
| 429    | `TOO_MANY_REQUESTS`     | Rate limit exceeded                                                        |
| 424    | `FAILED_DEPENDENCY`     | Upload could not be verified                                               |
| 401    | `UNAUTHORIZED_ACCESS`   | Missing or invalid API key                                                 |
